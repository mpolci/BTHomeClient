# Live screen simplification experiment

Status: rejected by the owner. Restore `prototype.html` as the active prototype; retain this experiment only as a record of the explored alternative.

## Feedback

The owner found the live screen increasingly crowded after the history action was moved onto an additional row. The issue now calls for revisiting the information and action hierarchy, rather than moving another label.

## Alternative

The `prototype-clean.html` variant separates routine reading from infrequent management:

- Live entries retain name, optional placement/photo, all readings, reception age, and reported battery charge.
- One global `Manage` entry replaces the per-sensor overflow menus. It opens a list with Edit/Register and Information actions; Done returns to live.
- A small chart icon identifies history-capable registered sensors. `Live only` remains visible for sensors without history. The supported card remains directly actionable.
- The three repeated measurement headings are visually omitted for these illustrative temperature/humidity/pressure readings; values retain units and accessible measurement labels. This is an experiment, not a general rule for future quantities whose units alone may be ambiguous.
- Thin dividers replace individual card outlines, and there is no separate history-action row.

## Tradeoffs

Management takes an additional navigation step. The chart icon is less explicit than `History →`, so discoverability must be evaluated. Unit-only readings may need an alternative for more varied sensor capabilities. No confirmed requirement is silently removed: this variant deliberately tests revisions to previously approved presentation choices.

## Artifacts and verification

The existing `prototype.html` retains its card menus and explicit history row. `prototype-clean.html` uses the same state and history/editor implementations with alternative presentation, generated by `wireframes/build_prototype.py`.

The simplified live list was visually inspected in the browser. Manage → Edit → Cancel → management list was exercised successfully. This is an illustrative in-memory prototype; it does not change the Android app.
